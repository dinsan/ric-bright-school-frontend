# Decisions worth knowing

> Moved from the README; kept up to date with the code.

## Decisions worth knowing

- **One app, plus one optional service**: pages, API and database access ship together. The browser only ever talks to this site, so there is no CORS. Server Components read the database through the services directly; the browser goes through `/api`. See [`docs/backend.md`](backend.md). The one other service is the **formula engine** (`services/formula-engine`, Python): maths is better done with SymPy and SciPy than in JavaScript, so it runs on its own, reached by the app's server only; the app keeps working without it (formula pages show LaTeX, the calculator says it's unavailable).
- **Maths without a maths library**: formulas are drawn as MathML, which browsers render natively; the engine sends MathML as a JSON tree that the app checks against an allowlist and builds with React. No KaTeX/MathJax in the bundle, nothing inserted as HTML.
- **ORM**: Prisma 7. The schema is `prisma/schema.prisma`, the generated client is fully typed, and migrations are plain SQL files generated from the schema and reviewed in pull requests (a few things Prisma can't express, like CHECK constraints and the generated search columns, are written by hand in the SQL). Queries run through the node-postgres driver adapter, with no query-engine binary, so the standalone Docker image stays small; full-text search uses typed raw SQL. See "Database" in [`docs/backend.md`](backend.md) and the migration notes in [`docs/prisma-migration.md`](prisma-migration.md).
- **Shared contract**: the JSON types in `src/features/auth/contract.ts` and `src/features/catalog/types.ts` are imported by both the browser code and the server that produces them, so the compiler catches a mismatch on either side.
- **Sessions**: random tokens in httpOnly, SameSite=Lax cookies; the database stores only their SHA-256. Signing out elsewhere, password changes and turning an account off take effect on the next request ([`docs/auth.md`](auth.md)).
- **Rendering**: the home page is static and refreshed from the database every 5 minutes; the course list shell and the legal pages are static. Course pages are rendered from the database on first visit and cached (incremental static regeneration, refreshed at most once a minute), and show a skeleton (`loading.tsx`) while they load. Unknown courses answer with HTTP 404. `sitemap.xml` is rendered on request so it always lists every published course. Builds need no database.
- **SEO**: every public page has a canonical URL, Open Graph and Twitter cards (share images drawn by `next/og`, one per course), and structured data (schema.org `Course`, `EducationalOrganization`, `WebSite`). Signed-in areas, sign-in pages and one-time links are noindex.
- **Legal texts are code**: the policies describe what the code really does, and the cookie table is generated from the cookie and storage constants (a test fails if one is added without a description). Company details live in `src/config/legal.ts`; until a lawyer has reviewed them, the pages say they are a draft.
- **URL state**: course search filters live in the URL, so filtered views are shareable and the back button works.
- **One database client per process**: `getDb()` keeps the Prisma Client on `globalThis` and every server bundle of a production build shares it; only `next dev` swaps it for a regenerated client. (Swapping it in production made concurrent requests close each other's client.)
- **Student data**: learning progress is stored per lesson and per day, never as a stream of events, and only the student and their parents can see it. Learning numbers are computed by shared pure functions, so the server and the browser always agree.
- **Errors**: the API answers every error in one envelope with a request id; the browser's API client turns it into a typed `ApiError`. An unreachable database is a 503 ("try again"), never a sign-out. The error page logs the error and shows its reference (`digest`) to quote to support.
- **Design tokens only**: components use semantic colours (`bg-surface`, `text-fg-muted`); Tailwind's default palette is switched off so a theme can change everything in one place. Contrast is checked by `npm run tokens:check`.
- **Themes and reading level**: light, dark and high contrast, plus a grade band (Grades 1–5, 6–8, 9–12) that changes text size, target size and density. Both are remembered on the device and applied by a small inline script before the page paints, so there is no flash.
- **Font**: Lexend, chosen for legibility for young readers, is self-hosted from `src/app/fonts/` through `next/font/local` (SIL OFL 1.1). Builds do not need internet access to Google Fonts.
- **Class names**: `cn()` combines `clsx` and `tailwind-merge`, so a class passed in by the caller overrides a conflicting default (for example `shadow-none` over `shadow-sticker`).
- **Footer year**: fixed at build time, so static and server-rendered pages always agree.
- **Self-study, no teachers**: Lumina has three roles, student, parent and admin. Students and parents sign in on separate pages (`portalRoles`), parents set goals for their children, and nobody messages anyone. Teachers, classes, assigned work and parent–teacher messages were removed in the `20261118120000_self_study` migration; [`self-study-plan.md`](self-study-plan.md) has the reasoning.
- **Goals are computed, not stored**: a goal's progress is worked out on every read from the child's learning, by pure functions shared by the child's and the parent's views; only "met" moments are stored, once each, so celebrations and history never double count.
- **Help is code, public and for everyone**: help topics are TypeScript in `src/features/help/content/` (one file per audience: getting started, students, parents, staff), reviewed with the features they describe, and tests check every page, link and linked topic exists. They are shown two ways: the **?** button on every page (from the home page on, signed in or not) and the static, public help centre at `/help`, so families can read it before signing up. Signed in, the panel shows a person only their own help; on public pages it searches everything. The topics load in the background after the page, so they add nothing to first loads. No outside help-desk service is needed.
